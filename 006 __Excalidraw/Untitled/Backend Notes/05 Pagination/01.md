# Pagination
- Pagination is splitting a large list of data into smaller chunks ( page ) instead of returning everything in one API response. 

#### Two common approaches
 - Offset-based pagination 
	 - uses page and limit 

```ts
GET /users?page=2&limit-10
```

- Cursor-based pagination

```ts
GET /users?cursor=105&limit=10
```

----
## Offset-based pagination
- 1 to 100 and you want 10 users per page

|Request|Offset|Returned IDs|
|---|---|---|
|`?page=1&limit=10`|0|1–10|
|`?page=2&limit=10`|10|11–20|
|`?page=3&limit=10`|20|21–30|

The Formula is 
```css
				offset  = ( page - 1 ) x limit  
```

```ts
               `http://localhost:3000/users?page=1&limit=10`
               `http://localhost:3000/users?page=2&limit=10`


import express, { Request, Response } from "express";

const app = express();

type User = {
  id: number;
  name: string;
};

// Example data (replace with a database query)
const users: User[] = Array.from(
  { length: 100 },
  (_, i) => ({
    id: i + 1,
    name: `User ${i + 1}`,
  })
);

app.get("/users", (req: Request, res: Response) => {
  const page = Math.max(1, Number(req.query.page) || 1);
  const limit = Math.min(100, Math.max(1, Number(req.query.limit) || 10));

  const offset = (page - 1) * limit;

  const data = users.slice(offset, offset + limit);

  res.json({
    page,
    limit,
    total: users.length,
    totalPages: Math.ceil(users.length / limit),
    data,
  });
});

app.listen(3000, () => {
  console.log("Server running on http://localhost:3000");
});
```

## Cursor-based pagination
- instead of saying "go to page 2" , you day " give me users after  ID  10."

| Request               | Meaning                  | Returned IDs |
| --------------------- | ------------------------ | ------------ |
| `?limit=10`           | Start from the beginning | 1–10         |
| `?cursor=10&limit=10` | Continue after ID 10     | 11–20        |
| `?cursor=20&limit=10` | Continue after ID 20     | 21–30        |

```ts

           `GET http://localhost:3000/users/cursor?cursor=3&limit=3`
app.get("/users/cursor", (req: Request, res: Response) => {
    const limit = Math.min(100, Math.max(1, Number(req.query.limit) || 10));

    const rawCursor = req.query.cursor;
    const cursor =
      typeof rawCursor === "string" &&
      /^\d+$/.test(rawCursor)
        ? Number(rawCursor)
        : null;

    // Return users after the cursor ID.
    const filteredUsers = users
      .filter((user) =>
        cursor === null || user.id > cursor
      )
      .sort((a, b) => a.id - b.id);

    // Fetch one extra item to detect another page.
    const results = filteredUsers.slice(0, limit + 1);

    const hasNextPage = results.length > limit;
    const data = results.slice(0, limit);

    res.json({
      limit,
      data,
      nextCursor:
        hasNextPage && data.length > 0
          ? data[data.length - 1].id
          : null,
      hasNextPage,
    });
  }
);
```

---

| Feature              | Offset-based                                             | Cursor-based                                 |
| -------------------- | -------------------------------------------------------- | -------------------------------------------- |
| Parameters           | `page`, `limit`                                          | `cursor`, `limit`                            |
| Jump to page 10      | Easy                                                     | Not naturally supported                      |
| Large datasets       | Large offsets can be slow                                | Often more efficient                         |
| New records inserted | Can cause duplicates or skipped records between requests | More stable with a consistent ordering       |
| Implementation       | Simpler                                                  | Slightly more involved                       |
| Best for             | Admin tables, numbered pages                             | News feeds, social media, infinite scrolling |

- ###  offset 
	skip some records, than take a number of records.
- ### Cursor
	Continue after the last record you received.

# Keyset Pagination 
- Fetches the next set of records using the values of the last record you received, rather than counting how many records to skip.

```ts

import express, { Request, Response } from "express";

const app = express();

type User = {
  id: number;
  name: string;
};

const users: User[] = Array.from(
  { length: 100 },
  (_, i) => ({
    id: i + 1,
    name: `User ${i + 1}`,
  })
);

app.get("/users", (req: Request, res: Response) => {
  const limit = Math.min(
    100,
    Math.max(1, Number(req.query.limit) || 10)
  );

  const rawCursor = req.query.cursor;

  const cursor =
    typeof rawCursor === "string" &&
    /^\d+$/.test(rawCursor)
      ? Number(rawCursor)
      : null;

  const filteredUsers = users
    .filter(user => cursor === null || user.id > cursor)
    .sort((a, b) => a.id - b.id);

  // Fetch one extra record to check for another page.
  const results = filteredUsers.slice(0, limit + 1);

  const hasNextPage = results.length > limit;
  const data = results.slice(0, limit);

  res.json({
    data,
    hasNextPage,
    nextCursor:
      hasNextPage && data.length > 0
        ? data[data.length - 1].id
        : null,
  });
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
```


|Feature|Offset|Cursor-based|Keyset|
|---|---|---|---|
|How it works|Skips rows|Continues from a cursor|Filters by ordered key values|
|Typical SQL|`OFFSET 20`|Depends on cursor design|`WHERE id > 20`|
|Large datasets|Large offsets can be expensive|Depends on implementation|Efficient with suitable indexes|
|Numbered page navigation|Easy|Usually not|Usually not|
|Stable ordering needed|Yes|Usually|Yes|



## Real-world examples

| Use case                                 | Recommended approach    |
| ---------------------------------------- | ----------------------- |
| Admin users table with page numbers      | Offset                  |
| Social media feed                        | Keyset                  |
| E-commerce products with page numbers    | Offset                  |
| Millions of database records             | Keyset                  |
| Recent orders, newest first              | Keyset                  |
| Small settings list                      | No pagination or offset |
| Exporting millions of records in batches | Keyset, often           |
