
## Rate Limiting 
- is a technique used to control how many requests a client can make to a server within a specific time period.
Example
- API might allow use to 100 requests per minute,
- if User hit that limit the server temporarily rejects additional  requests.

#### Rate limiting helps prevent:

Brute-force attacks
DDoS and traffic abuse
Server overload 
API abuse : One user consuming to much of a shared resource.

```ts
import express from "express";
import rateLimit from "express-rate-limit";

const app = express();

const limiter = rateLimit({
  windowMs: 60 * 1000, // 1 minute
  limit: 5,            // 5 requests per window
  standardHeaders: "draft-8",
  legacyHeaders: false,
});

app.use("/api", limiter);

app.get("/api/users", (req, res) => {
  res.json({ message: "Users fetched successfully" });
});

app.listen(3000);
```

#### Where should rate limiting be implemented?
- API gateway : Limits requests before they reach your application,
- Backend Middleware
- Redis
- Database / Business logic 

#### Rate limiting vs. throttling
- Rate Limiting : defines the maximum allowed request rate.
- Throttling : can mean slowing down, delaying. or restricting traffic when a system is under pressure.
----
## . Which rate-limiting algorithm should you choose?

|Requirement|Suitable approach|
|---|---|
|Allow bursts, limit average request rate|Token Bucket|
|Allow bursts, smooth outgoing traffic|Leaky Bucket|
|Simple limit per minute|Fixed Window|
|Limit requests over a rolling time period|Sliding Window|
|Limit simultaneous jobs|Concurrency limiter|
|Limit API calls per day or month|Quota counter|

## Real-world examples for Express.js

| Endpoint                                         | Recommended approach                                              |
| ------------------------------------------------ | ----------------------------------------------------------------- |
| `GET /api/products`,<br>`GET /api/notifications` | Token Bucket                                                      |
| `POST/api/reports/generate`                      | Token Bucket + job queue/concurrency limit                        |
| `POST /api/login`                                | Strict rate limiting + account-level abuse protections            |
| `POST /api/payment`                              | Rate limiting + idempotency + payment validation                  |
| `GET /api/usage`                                 | Per-user quota or rolling-window limit, depending on requirements |
| `POST /api/upload`                               | Rate limiting + file-size limits + storage quotas                 |
